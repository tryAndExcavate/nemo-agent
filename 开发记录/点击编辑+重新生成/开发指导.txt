# 消息编辑 + 重新生成 — 前后端设计方案

这个功能的本质是把"线性对话历史"升级成"**树形对话历史**"——每次编辑或重新生成，都是在某个节点下开一个新的兄弟分支，用户可以在分支间自由切换。这是目前主流对话产品（ChatGPT/Claude）的标准做法。

---

## 一、需求范围界定

| 操作 | 触发条件 | 效果 |
|---|---|---|
| **编辑用户消息** | 鼠标悬停在自己发的消息上，点编辑 | 修改内容后下面存在两个按键 一个是不分支重新回复，另一个是分支重新回复。
若是分支重新恢复则从这条消息开始产生新分支，之后的对话暂时不显示（但保留，可切回） |
| **重新生成AI回复** | 鼠标悬停在AI回复上，点重新生成 | 此处不做分支处理 |
| **切换分支** | 若之前存在分支消息则下方出现"◀ 2/3 ▶"切换器 | 展示同一父节点下的不同版本，互不影响 |

不做的范围（先明确，避免过度设计）：不做"分支合并"、不做"多人协作分支树可视化"，只做最基础的"编辑/重新生成/线性切换浏览"。

## 二、数据模型设计（树形结构改造）

#ai_session 表改造：支持分支树结构
SQL

ALTER TABLE `ai_session`
  ADD COLUMN `parent_id` bigint DEFAULT NULL
      COMMENT '父轮次ID（对应本表id），NULL表示该会话的第一轮对话' AFTER `session_id`,
  ADD COLUMN `is_active_branch` tinyint(1) NOT NULL DEFAULT 1
      COMMENT '是否在当前激活分支路径上：1=是，0=已被切换掉的历史分支' AFTER `parent_id`,
  ADD COLUMN `edit_source_id` bigint DEFAULT NULL
      COMMENT '若本轮是编辑/重新生成产生的新分支，记录原始轮次id，便于追溯' AFTER `is_active_branch`,
  ADD COLUMN `is_edited` tinyint(1) NOT NULL DEFAULT 0
      COMMENT '是否由编辑问题产生的分支' AFTER `edit_source_id`,
  ADD COLUMN `is_regenerated` tinyint(1) NOT NULL DEFAULT 0
      COMMENT '是否由重新生成回答产生的分支' AFTER `is_edited`,
  ADD COLUMN `model_id` varchar(64) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci DEFAULT NULL
      COMMENT '生成本轮回答所使用的模型ID，对应可插拔基座的模型配置id' AFTER `agent_type`,
  ADD COLUMN `token_count` int DEFAULT NULL
      COMMENT '本轮问答（question+answer）的token总数，供上下文压缩预算计算使用' AFTER `total_response_time`,
  ADD INDEX `idx_session_active` (`session_id`, `is_active_branch`) USING BTREE,
  ADD INDEX `idx_parent_id` (`parent_id`) USING BTREE;

parent_id 是自引用外键（指向本表 id），不加物理外键约束——因为 ai_session 表历史数据量可能较大，加约束会触发全表校验锁表，建议靠应用层保证一致性
token_count 直接加在这张表上，和你已有的 first_response_time/total_response_time 风格保持一致，方便后续上下文压缩模块直接查询这张表算预算，不需要额外表


#conversations 表改造：记录当前分支状态
SQL

ALTER TABLE `conversations`
  ADD COLUMN `current_leaf_turn_id` bigint DEFAULT NULL
      COMMENT '当前激活分支的叶子轮次ID，对应ai_session.id' AFTER `title`,
  ADD COLUMN `root_turn_id` bigint DEFAULT NULL
      COMMENT '该会话的根轮次ID，对应ai_session.id' AFTER `current_leaf_turn_id`;


从叶子节点回溯到根节点，还原完整分支路径
SQL

WITH RECURSIVE turn_path AS (
    SELECT id, parent_id, question, answer, model_id, 0 AS depth
    FROM ai_session
    WHERE id = :leaf_turn_id
    UNION ALL
    SELECT s.id, s.parent_id, s.question, s.answer, s.model_id, tp.depth + 1
    FROM ai_session s
    INNER JOIN turn_path tp ON s.id = tp.parent_id
)
SELECT * FROM turn_path ORDER BY depth DESC;
#获取当前激活分支的完整对话（渲染用，走索引）
SQL

SELECT id, question, answer, model_id, is_edited, is_regenerated, create_time
FROM ai_session
WHERE session_id = :session_id AND is_active_branch = 1
ORDER BY id ASC;
#获取某轮次的所有兄弟分支（用于切换器展示）
SQL

SELECT id, question, answer, create_time
FROM ai_session
WHERE session_id = :session_id
  AND (parent_id = :parent_id OR (:parent_id IS NULL AND parent_id IS NULL))
ORDER BY id ASC;
#切换分支：先回溯路径，再批量更新激活标记
SQL

-- 第一步：用5.1的递归CTE查出 path_ids 列表（应用层拿到后传入下一步）

-- 第二步：整个会话先清零
UPDATE ai_session SET is_active_branch = 0 WHERE session_id = :session_id;

-- 第三步：路径上的节点重新置1
UPDATE ai_session SET is_active_branch = 1 WHERE id IN (:path_ids);

-- 第四步：更新会话的当前叶子指针
UPDATE conversations SET current_leaf_turn_id = :leaf_turn_id WHERE session_id = :session_id;


### 2.3 一个具体例子帮助理解

```
msg_1 (user: "你好")
  └─ msg_2 (assistant: "你好！有什么可以帮你")
       ├─ msg_3 (user: "介绍下Python")        ← 分支A（原始）
       │    └─ msg_4 (assistant: "Python是...")
       └─ msg_5 (user: "介绍下Python是什么语言")  ← 分支B（编辑后的新分支）
            └─ msg_6 (assistant: "Python是一门...")
```

如果用户当前在分支B，`current_leaf_message_id = msg_6`，`is_active_branch=1` 的节点是 `msg_1, msg_2, msg_5, msg_6`。

## 三、后端接口设计

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/messages/{message_id}/edit` | POST | 编辑一条用户消息，创建新分支并触发重新生成 |
| `/api/messages/{message_id}/regenerate` | POST | 对某条AI回复重新生成，创建兄弟分支 |
| `/api/messages/{message_id}/siblings` | GET | 获取该消息的所有兄弟分支（用于切换器展示 1/3、2/3）|
| `/api/conversations/{id}/switch_branch` | POST | 切换到指定叶子节点，更新 `current_leaf_message_id` |
| `/api/conversations/{id}/messages` | GET | 获取当前激活分支的完整消息列表（渲染对话用）|

### 3.1 数据访问层：树形操作核心逻辑

```python
# repository/message_tree_repo.py
from typing import List, Dict, Optional
from sqlalchemy import text


class MessageTreeRepository:
    def __init__(self, db_session_factory):
        self.db_session_factory = db_session_factory

    async def get_active_path(self, conversation_id: int) -> List[Dict]:
        """获取当前激活分支的完整消息列表，用于渲染对话和构造发给模型的上下文"""
        async with self.db_session_factory() as session:
            result = await session.execute(
                text("""
                    SELECT id, role, content, parent_id, created_at
                    FROM messages
                    WHERE conversation_id = :cid AND is_active_branch = 1
                    ORDER BY id ASC
                """),
                {"cid": conversation_id}
            )
            return [dict(r._mapping) for r in result.fetchall()]

    async def get_siblings(self, message_id: int) -> List[Dict]:
        """获取某条消息的所有兄弟节点（同一parent_id下的所有版本），用于分支切换器"""
        async with self.db_session_factory() as session:
            target = await session.execute(
                text("SELECT parent_id, conversation_id FROM messages WHERE id = :mid"),
                {"mid": message_id}
            )
            row = target.first()
            if not row:
                return []
            parent_id = row.parent_id

            if parent_id is None:
                result = await session.execute(
                    text("""
                        SELECT id, content, created_at FROM messages
                        WHERE conversation_id = :cid AND parent_id IS NULL
                        ORDER BY id ASC
                    """),
                    {"cid": row.conversation_id}
                )
            else:
                result = await session.execute(
                    text("""
                        SELECT id, content, created_at FROM messages
                        WHERE parent_id = :pid ORDER BY id ASC
                    """),
                    {"pid": parent_id}
                )
            return [dict(r._mapping) for r in result.fetchall()]

    async def insert_message(
        self, conversation_id: int, role: str, content: str, parent_id: Optional[int]
    ) -> int:
        async with self.db_session_factory() as session:
            result = await session.execute(
                text("""
                    INSERT INTO messages (conversation_id, role, content, parent_id, is_active_branch)
                    VALUES (:cid, :role, :content, :pid, 1)
                """),
                {"cid": conversation_id, "role": role, "content": content, "pid": parent_id}
            )
            await session.commit()
            return result.lastrowid

    async def switch_branch(self, conversation_id: int, leaf_message_id: int):
        """
        切换到指定叶子节点：
        1. 从叶子回溯到根，得到完整路径
        2. 该会话下所有消息先标记 is_active_branch=0
        3. 路径上的消息标记 is_active_branch=1
        4. 更新 conversations.current_leaf_message_id
        """
        async with self.db_session_factory() as session:
            path_ids = await self._trace_path_to_root(session, leaf_message_id)

            async with session.begin():
                await session.execute(
                    text("UPDATE messages SET is_active_branch = 0 WHERE conversation_id = :cid"),
                    {"cid": conversation_id}
                )
                if path_ids:
                    await session.execute(
                        text("""
                            UPDATE messages SET is_active_branch = 1
                            WHERE id IN :ids
                        """).bindparams(ids=tuple(path_ids)),
                        {}
                    )
                await session.execute(
                    text("UPDATE conversations SET current_leaf_message_id = :leaf WHERE id = :cid"),
                    {"leaf": leaf_message_id, "cid": conversation_id}
                )

    async def _trace_path_to_root(self, session, leaf_id: int) -> List[int]:
        path = []
        current_id = leaf_id
        while current_id is not None:
            result = await session.execute(
                text("SELECT id, parent_id FROM messages WHERE id = :mid"),
                {"mid": current_id}
            )
            row = result.first()
            if not row:
                break
            path.insert(0, row.id)
            current_id = row.parent_id
        return path
```

### 3.2 业务逻辑层：编辑 & 重新生成

```python
# services/edit_regenerate_service.py
from repository.message_tree_repo import MessageTreeRepository
from llm_service import llm_service


class EditRegenerateService:
    def __init__(self, tree_repo: MessageTreeRepository):
        self.tree_repo = tree_repo

    async def edit_user_message(
        self, conversation_id: int, message_id: int, new_content: str, system_prompt: str
    ) -> dict:
        """
        编辑用户消息：
        1. 找到被编辑消息的 parent_id（这条新消息应该和原消息是兄弟关系）
        2. 插入新的用户消息节点
        3. 基于这个新节点，调用模型生成回复，插入为它的子节点
        4. 切换到这个新分支
        """
        original = await self._get_message(message_id)
        if not original or original["role"] != "user":
            raise ValueError("只能编辑用户消息")

        # 新消息作为原消息的兄弟节点（同一个parent_id）
        new_user_msg_id = await self.tree_repo.insert_message(
            conversation_id, "user", new_content, original["parent_id"]
        )

        return await self._generate_reply_branch(
            conversation_id, new_user_msg_id, system_prompt
        )

    async def regenerate_assistant_message(
        self, conversation_id: int, message_id: int, system_prompt: str
    ) -> dict:
        """
        重新生成AI回复：
        1. 找到被重新生成消息的 parent_id（通常是上一条用户消息）
        2. 直接基于这个parent_id生成新回复，作为兄弟节点插入
        """
        original = await self._get_message(message_id)
        if not original or original["role"] != "assistant":
            raise ValueError("只能对AI回复执行重新生成")

        return await self._generate_reply_branch(
            conversation_id, original["parent_id"], system_prompt
        )

    async def _generate_reply_branch(self, conversation_id, parent_msg_id, system_prompt) -> dict:
        """
        公共逻辑：给定一个父节点（通常是用户消息），
        走完整的上下文压缩+模型调用流程，生成新的assistant回复节点
        """
        # 关键：这里需要按 parent_msg_id 重建"到这个节点为止"的历史，
        # 而不是用当前激活分支的历史 —— 因为可能是在编辑一条较早的消息
        history_up_to_parent = await self._build_history_up_to(parent_msg_id)
        current_input = history_up_to_parent[-1]["content"]  # 触发生成的那条用户消息
        history_for_context = history_up_to_parent[:-1]      # 该消息之前的历史

        result = await llm_service.chat_with_history(
            conversation_id=conversation_id,
            system_prompt=system_prompt,
            history=history_for_context,   # 复用之前设计的三层压缩逻辑
            current_input=current_input,
        )

        new_assistant_msg_id = await self.tree_repo.insert_message(
            conversation_id, "assistant", result.content, parent_msg_id
        )

        # 生成完成后，自动切换到这条新分支（用户体验：编辑/重新生成后直接看到新结果）
        await self.tree_repo.switch_branch(conversation_id, new_assistant_msg_id)

        return {
            "new_user_message_id": parent_msg_id,
            "new_assistant_message_id": new_assistant_msg_id,
            "content": result.content,
            "usage": result.usage.dict(),
        }

    async def _build_history_up_to(self, message_id: int) -> list:
        """从根节点走到指定消息节点的完整路径（不依赖当前is_active_branch状态）"""
        path_ids = await self.tree_repo._trace_path_to_root_public(message_id)
        # 按path_ids批量查询消息内容，按顺序返回
        ...  # 实现从略，逻辑同 _trace_path_to_root，只是最后多一步按id批量取content

    async def _get_message(self, message_id: int) -> dict:
        ...  # SELECT * FROM messages WHERE id = message_id
```

**关键设计点说明**：编辑/重新生成时，**必须按目标节点重新回溯路径构建历史**，而不是简单复用"当前展示的对话列表"——因为用户可能是在编辑很早之前的一条消息，这时候要基于"那条消息之前的历史"来生成，和当前正在看的分支完全无关。

### 3.3 路由层

```python
# routers/edit_regenerate.py
from fastapi import APIRouter, HTTPException, Depends
from pydantic import BaseModel
from services.edit_regenerate_service import EditRegenerateService

router = APIRouter(prefix="/api/messages", tags=["message-edit"])


class EditMessageRequest(BaseModel):
    new_content: str
    system_prompt: str = "你是一个有帮助的助手"


class RegenerateRequest(BaseModel):
    system_prompt: str = "你是一个有帮助的助手"


@router.post("/{message_id}/edit")
async def edit_message(
    message_id: int,
    conversation_id: int,
    req: EditMessageRequest,
    service: EditRegenerateService = Depends(get_edit_service),
):
    try:
        result = await service.edit_user_message(
            conversation_id, message_id, req.new_content, req.system_prompt
        )
        return result
    except ValueError as e:
        raise HTTPException(400, str(e))


@router.post("/{message_id}/regenerate")
async def regenerate_message(
    message_id: int,
    conversation_id: int,
    req: RegenerateRequest,
    service: EditRegenerateService = Depends(get_edit_service),
):
    try:
        result = await service.regenerate_assistant_message(
            conversation_id, message_id, req.system_prompt
        )
        return result
    except ValueError as e:
        raise HTTPException(400, str(e))


@router.get("/{message_id}/siblings")
async def get_siblings(
    message_id: int,
    repo: MessageTreeRepository = Depends(get_tree_repo),
):
    siblings = await repo.get_siblings(message_id)
    return {"siblings": siblings, "total": len(siblings)}


@router.post("/conversations/{conversation_id}/switch_branch")
async def switch_branch(
    conversation_id: int,
    leaf_message_id: int,
    repo: MessageTreeRepository = Depends(get_tree_repo),
):
    await repo.switch_branch(conversation_id, leaf_message_id)
    return {"status": "ok"}
```

### 4.3 JS 核心逻辑

```javascript
const API_BASE = "http://127.0.0.1:8000";
let currentConversationId = null;
const siblingCache = {}; // message_id -> {siblings: [...], currentIndex: n}

// ---------- 编辑用户消息 ----------
function startEdit(messageId) {
  const contentEl = document.getElementById(`content-${messageId}`);
  const originalText = contentEl.textContent;
  contentEl.classList.add("editing");
  contentEl.innerHTML = `
    <textarea id="edit-input-${messageId}">${originalText}</textarea>
    <div class="edit-actions">
      <button class="btn-cancel-edit" onclick="cancelEdit(${messageId}, '${escapeForJs(originalText)}')">取消</button>
      <button class="btn-save-edit" onclick="submitEdit(${messageId})">保存并重新生成</button>
    </div>
  `;
  document.getElementById(`edit-input-${messageId}`).focus();
}

function cancelEdit(messageId, originalText) {
  const contentEl = document.getElementById(`content-${messageId}`);
  contentEl.classList.remove("editing");
  contentEl.textContent = originalText;
}

async function submitEdit(messageId) {
  const newContent = document.getElementById(`edit-input-${messageId}`).value.trim();
  if (!newContent) return;

  showGeneratingIndicator(); // 展示"正在生成..."的loading态

  const res = await fetch(`${API_BASE}/api/messages/${messageId}/edit?conversation_id=${currentConversationId}`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ new_content: newContent }),
  });

  hideGeneratingIndicator();

  if (res.ok) {
    // 编辑成功后，该消息及之后的所有分支都变了，最简单可靠的做法是重新拉取当前激活分支的完整消息列表
    await reloadActiveConversation();
  } else {
    alert("编辑失败，请重试");
  }
}

// ---------- 重新生成AI回复 ----------
async function regenerateMessage(messageId) {
  showGeneratingIndicator();

  const res = await fetch(`${API_BASE}/api/messages/${messageId}/regenerate?conversation_id=${currentConversationId}`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({}),
  });

  hideGeneratingIndicator();

  if (res.ok) {
    await reloadActiveConversation();
  } else {
    alert("重新生成失败，请重试");

}

// ---------- 分支切换 ----------
async function loadSiblingInfo(messageId) {
  const res = await fetch(`${API_BASE}/api/messages/${messageId}/siblings`);
  const data = await res.json();
  const currentIndex = data.siblings.findIndex(s => s.id === messageId);
  siblingCache[messageId] = { siblings: data.siblings, currentIndex };
  return siblingCache[messageId];
}

async function renderBranchSwitcher(messageId) {
  const info = await loadSiblingInfo(messageId);
  const switcherEl = document.getElementById(`switcher-${messageId}`);
  if (info.siblings.length <= 1) {
    switcherEl.style.display = "none";
    return;
  }
  switcherEl.style.display = "flex";
  document.getElementById(`switcher-label-${messageId}`).textContent =
    `${info.currentIndex + 1}/${info.siblings.length}`;
}

async function switchSibling(messageId, direction) {
  const info = siblingCache[messageId];
  if (!info) return;
  const newIndex = info.currentIndex + direction;
  if (newIndex < 0 || newIndex >= info.siblings.length) return;

  const targetSibling = info.siblings[newIndex];

  // 这条兄弟消息下面可能还有自己的子树，需要找到它这一支最新的叶子节点
  // 简化处理：如果后端在siblings接口里能顺带返回每个分支的"最新叶子id"会更准确
  // 这里演示直接切到该兄弟节点本身（如果它还有子节点，可再进一步查询该分支最深的叶子）
  const res = await fetch(
    `${API_BASE}/api/messages/conversations/${currentConversationId}/switch_branch?leaf_message_id=${targetSibling.id}`,
    { method: "POST" }
  );
  if (res.ok) {
    await reloadActiveConversation();
  }
}

// ---------- 重新拉取当前激活分支并渲染 ----------
async function reloadActiveConversation() {
  const res = await fetch(`${API_BASE}/api/conversations/${currentConversationId}/messages`);
  const data = await res.json();
  renderMessageList(data.items); // 复用你已有的消息列表渲染逻辑
  // 对每条有多个兄弟版本的消息渲染分支切换器
  data.items.forEach(msg => renderBranchSwitcher(msg.id));
}

function escapeForJs(str) {
  return str.replace(/'/g, "\\'").replace(/\n/g, "\\n");
}
```

**关于"切到兄弟分支后要展示它最深的子树叶子"这一点**：目前代码里做了简化处理（直接切到兄弟节点本身），实际生产中建议在 `siblings` 接口的返回结果里，给每个兄弟节点顺带查出它这条分支上最新的叶子节点id（可以在 `get_siblings` 方法里为每个sibling递归查一次"最深子节点"），这样切换分支后能自动展示到该分支最新的对话进度，而不是每次都要重新往下点。

## 七、需要留意的边界情况

1. **编辑第一条消息（根节点）**：`parent_id` 为 `NULL`，兄弟节点查询逻辑要单独处理（代码里已经区分了这种情况）
2. **正在生成中时点击编辑/重新生成**：需要先调用停止生成接口，或者前端直接禁用编辑按钮直到当前生成结束，避免并发写入混乱
3. **分支越删越多的存储膨胀**：树形结构会让消息数量比线性历史多不少，长期看可以做一个"清理从未被访问的旧分支"的后台任务，但这个不用在本期考虑，先把功能做通
