# 3D 分支对话系统 — 前端使用说明

## 一、整体概念

这套界面把一次会话内的所有问答，按照数据库里的 `parent_id` 关系组织成一棵**树**。树上每一个"层级"（即同一个 `parent_id` 下的所有节点）会被渲染成一摞可以左右翻阅的**3D 书页**，页与页之间是**并列关系**，彼此独立、互不覆盖。

你可以把整个界面理解成：

```
根问题（普通气泡）
   └─ 第 1 层书本：分支 A / 分支 B / 分支 C   ← 同层并列，随便翻
         └─ 分支 A 内部又有第 2 层书本：子分支 A-1 / A-2
               └─ 子分支还能再往下长出第 3 层……
```

层数不是固定的，取决于数据库里实际有多深的父子关系。

---

## 二、页面区域说明

| 区域 | 位置 | 作用 |
|---|---|---|
| 顶部提示条 | 页面最上方 | 文字说明当前操作规则 |
| 🧭 回到主线分支 | 顶部右侧按钮 | 一键把所有层级的书本都翻回 `is_active_branch=1` 标记的那一页 |
| 根问答气泡 | 顶部提示条下方 | `parent_id IS NULL` 的那条记录，固定展示，不参与翻页 |
| 书页舞台（Stage） | 每一层书本的主体 | 当前层所有并列分支重叠展示的 3D 区域，同一时刻只有一页在最前 |
| 标签栏（Tab） | 舞台右侧（第 1 层）/ 舞台上方（第 2 层及以后） | 点击可以切换"当前查看哪一页" |
| ＋ 新增分支 标签 | 标签栏最后一个 | 点击后在当前层新增一条并排的空白分支 |

**视觉规则**：
- 第 1 层（最外层）用**竖排深色标签**贴在书本右侧，模拟书脊索引；
- 第 2 层及更深层，用**横排药丸标签**摆在对应小书本上方，视觉上区分层级深浅。
- 每一页左侧的彩色竖条颜色会随层级加深而变化（蓝→绿→黄→紫→红循环），方便你一眼判断"现在看的是第几层"。

---

## 三、核心操作说明

### 1. 切换查看某个分支（翻页）

直接点击标签栏里的任意一个标签，对应的书页就会以 3D 翻转动画转到最前面（`active` 状态），其余页会按照与它的距离层叠退到后面或翻到背面。

> 这个操作**只影响你正在看哪一页**，不会更改任何数据、不会影响其他分支的内容，可以随时来回切换，没有次数限制。

### 2. 新增一个"并排分支"（核心功能）

如果你想在当前这一层再开一条新的、独立的对话方向：

1. 点击标签栏最右侧的 **"＋ 新增分支"** 标签（第 1 层显示为"＋ 新增分支"，更深层显示为"＋ 新增"）；
2. 界面会自动生成一张**新的空白书页**并直接翻到最前面，页面顶部会有橙色 **"待发送"** 徽章；
3. 在文本框里输入你的新问题；
4. 点击 **"发送，生成该分支"**：
   - 会立即生成一条模拟回答；
   - 该分支正式生效，标签文字从"待填写"变为你输入的问题摘要，顶部橙色徽章消失，改为紫色 **"新增分支"** 徽章（用于区分它是本次会话中新增的，而非原始数据库记录）；
5. 如果输入到一半不想要了，点击 **"取消"**，这张草稿页会被直接移除，不会留下任何痕迹。

> 关键点：新增的分支和原有分支处于**完全相同的层级**（即相同的 `parent_id`），彼此是平级并排关系，**不是**在原分支基础上叠加或替换，原来的分支内容不受任何影响，你可以随时切换回去。

### 3. 进入某个分支的子分支

如果某个分支下面还挂着子分支（数据库里存在以它为 `parent_id` 的记录），打开这个分支页后，往下滚动会看到一个带虚线边框的区域，标注"该分支下有 N 个子分支"，下面就是这一层的子书本，交互方式和外层完全一致——切换标签翻页、点"＋新增"加分支都可以在这里独立进行。

子分支的翻页/新增操作只会影响它自己所在的层级，不会影响父级或兄弟分支。

### 4. 回到主线分支

顶部的 **"🧭 回到主线分支"** 按钮会把**所有层级**的书本同时复位到各自数据库标记的 `is_active_branch=1` 那一页。适合在你翻阅了很多分支之后，快速回到"系统认为的默认对话路径"，方便重新梳理主干逻辑。

> 注意：这个操作只是**视图复位**，不会删除你新增的任何分支，也不会清空草稿。

## 四、页面内信息说明

每一张正式生成的书页（非草稿状态）内部固定包含以下内容，从上到下：

| 内容 | 说明 |
|---|---|
| 标题行 | 编号圆点（对应 `branch_order`）+ 问题摘要 + 徽章（★主线 / 新增分支，可能同时出现或都不出现） |
| User 消息气泡 | 对应 `question` 字段完整内容 |
| Agent 消息气泡 | 对应 `answer` 字段完整内容 |
| meta 信息条 | 灰色小胶囊标签，依次展示：调用的工具（如有）、首字响应耗时、总响应耗时、token 数量、创建时间 |
| 参考资料块 | 如果 `reference` 字段有值，会以左侧灰色竖线标注的小卡片形式展示 |
| 子分支区域 | 如果存在子节点，展示子层书本（见上一节） |
| "＋ 新增并排分支"按钮 | 页面最底部，点击效果等同于点标签栏的"＋新增"，但入口更显眼 |

## 五、常见疑问

**Q：新增的分支会不会覆盖或影响原来已有的分支？**
不会。新增操作只是往同一层的数组里追加一条新记录，原有记录原封不动，切换标签即可查看，互相独立。

**Q：如果我新增了分支但没有点发送就切换到别的标签，草稿会丢失吗？**
草稿页会一直保留在标签栏里（显示"分支 N（待填写）"），只要没有主动点"取消"，随时可以再点回这个标签继续编辑、发送。

**Q：主线徽章（★主线）和是否为当前查看页有关系吗？**
没有直接关系。★主线只表示这条记录在数据库里 `is_active_branch=1`，是"默认应该看哪一页"的标记；而"当前查看哪一页"是纯前端的临时状态（`current` 变量），两者独立，你完全可以在查看非主线分支的同时，主线徽章依然显示在别的分支上。

**Q：为什么有的层级标签是竖排、有的是横排？**
纯粹是为了视觉上区分"最外层"和"内层嵌套"，不影响任何功能，操作方式完全一致。

## 六、后续可扩展方向（供参考，暂未在当前版本实现）

- **深度追问**：目前"新增分支"只能新增同层的兄弟节点，如果需要"基于当前这条回答继续往下追问"（即生成子节点而不是兄弟节点），需要额外增加一个"深入追问"按钮，走 `parent_id = 当前节点.id` 的新增逻辑。
- **真实接口对接**：当前"发送"后是本地模拟生成回答（`mockReply` 函数），实际接入时需要替换为真实的后端请求，并用返回结果填充 `answer`、`tools`、`token_count` 等字段。
- **删除/编辑已有分支**：当前只支持删除"未发送的草稿"，如果需要支持删除或编辑已经生成完的正式分支，需要额外补充确认弹窗和接口调用。
